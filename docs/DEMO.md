# Recorded integration demo

Run from the repository root with the existing Python environment and ffmpeg:

```sh
cargo build --release -p oblivion-server
.venv/bin/python scripts/record_demo.py experiments/results/demo-recording-NEW
```

The recording command launches the real release executable as
`oblivion-server demo-sse NEW_OUT 50 3 mixed`. It exercises eight epochs,
three clients, a deterministic half real workload, mixed WASM functions,
SSE metadata discovery, two encrypted PIR links, Path ORAM and padded
encrypted responses. The existing client oracle checks returned results
before the demo can exit successfully.

Use a new output name on each run. Raw component outputs stay in the
requested directory. The recorder writes the MP4, a representative PNG,
raw stdout/stderr, timestamped observed events, an asciicast v2 terminalcast,
text captions, evidence totals, ffprobe metadata and provenance under
`docs/artifacts/demo-<output-directory-name>/`. Dependencies are Python,
Matplotlib, ffmpeg/ffprobe and the built release binary; no network is used.

The MP4 is a **data-driven terminal visualization of an actual subprocess
run**, rendered after capture. Its progress counts come from completed,
flushed executor instrumentation rows observed by the recorder. These
timestamps describe when the recorder observed a row, rather than exact
guest completion times. The title and summary cards have explicit display
holds; the middle portion follows recorded wall time at one frame per second.
The terminalcast and raw logs preserve the captured events separately.

Provenance records the command, configuration, one trial, tool versions,
binary SHA-256 and per-file source SHA-256 **before** launch. Evidence also
hashes every output file. Source and executable hashes identify artifacts;
they do not prove that an independently supplied executable was built from
those sources. The demo's own metadata contains its separate source-tree
digest. Encoder inputs are temporary and cleaned up after rendering.

This demonstrates local API and inherited-pipe integration under a trusted
process simulation. It has no hardware TEE, and the two PIR servers must
not collude. It is not a screen recording, packet capture, statistical
privacy evaluation or hardware isolation proof.
